# AGENTS.md — Goldenland 2 Android Port

## Что это

Нативный порт игры **«Златогорье 2» v1.3** (движок GoldenLand 2) на **C++20 + SDL2** для Android.
Готового исходника движка не существует: порт — чистая реконструкция по декомпиляции
`Client.dll`/`Server.dll` и по документации форматов сообщества.

Цель: полная одиночная кампания, работающая нативно на Android.

## Обязательный порядок чтения перед любой задачей

1. `AGENTS.md` (этот файл).
2. `docs/STATUS.md` — где мы сейчас и какая задача следующая.
3. `docs/PROJECT.md` — цель, декомпозиция, границы подпроектов.
4. `docs/specs/<актуальный spec>.md` и `docs/plans/<актуальный plan>.md`.
5. `docs/DECISIONS.md` — принятые решения (не пересматривать без причины).

**Если чего-то нет в `docs/` — этого не существует.** История чата не является источником истины.

## Правила ведения контекста между задачами

- **Перед задачей:** обновить `docs/STATUS.md`: задача, критерии приёмки, команды проверки.
- **Во время работы:** новые факты о бинарниках/форматах/поведении — в `docs/research/`
  с указанием источника (файл, хэш, RVA/offset, инструмент).
- **После задачи:** обновить `docs/STATUS.md` (что сделано, чем проверено, что дальше),
  `docs/PROJECT.md` (статус подпроекта), при необходимости `docs/DECISIONS.md`.
- **Одна задача = один подпроект** из `PROJECT.md`. Не смешивать подпроекты в одной задаче.
- **Definition of Done:** код + тесты + реально выполненные команды проверки (с выводом) +
  обновлённые документы. Без доказательств задача не считается выполненной.
- Не оставлять «TBD/TODO» в spec: всё нерешённое — в `STATUS.md` → Open Questions.

## Технические правила

- Язык: **C++20**. Сборка: **CMake ≥ 3.20 + Ninja**. Графика/ввод/аудио: **SDL2**.
  Сжатие: **miniz**. Изображения: **stb_image**. Тесты: **doctest**. Форматирование: `.clang-format`.
- Слои и зависимости — только «вниз»:
  `platform` → `app` → `game`/`render`/`ui`/`audio` → `script`/`core` → `assets`.
  `assets` не зависит от SDL и ОС (только стандартная библиотека + miniz/stb).
- Оригинальная архитектура клиент-серверная. В одиночной игре клиент и сервер работают
  в одном процессе, но за чёткой границей (`ServerCore` / `ClientCore`), чтобы не потерять
  возможность мультиплеера в будущем.
- Данные: только чтение оригинальных файлов игры из каталога, указанного пользователем.
  **Ассеты игры не коммитить и не распространять.**
- Кодировки: внутри данных — cp1251/ASCII; на границе API — UTF-8.
- Пути в виртуальной ФС — регистронезависимые, разделители нормализуются.
- **DRM:** не использовать `protect.dll`/StarForce и не обходить защиту. Порт не запускает
  оригинальные бинарники; он читает только файлы данных.
- Логирование: `gl::log` с уровнями (`debug/info/warning/error`), без секретов.
- Имена: типы — `PascalCase`, функции/переменные — `snake_case`, файлы — `snake_case`.
- Не добавлять комментарии в код без необходимости.

## Команды (обновлять по мере появления)

```powershell
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug
cmake --build build
ctest --test-dir build --output-on-failure
build\bin\glpak.exe info "I:\Games\Златогорье-2"
```
