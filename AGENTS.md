# AGENTS.md — Goldenland 2 Android Port

## Что это

Нативный порт игры **«Златогорье 2» v1.3** (движок GoldenLand 2) на **C++20 + SDL2** для Android.
Готового исходника движка не существует: порт — чистая реконструкция по декомпиляции
`Client.dll`/`Server.dll` и по документации форматов сообщества.

Цель: полная одиночная кампания, работающая нативно на Android.

## Обязательный порядок чтения перед любой задачей

1. `AGENTS.md` (этот файл).
2. `docs/STATUS.md` — где мы сейчас и какая задача следующая.
3. `docs/PROJECT.md` — цель, декомпозиция, границы подпроектов.
4. `docs/specs/<актуальный spec>.md` и `docs/plans/<актуальный plan>.md`.
5. `docs/DECISIONS.md` — принятые решения (не пересматривать без причины).

**Если чего-то нет в `docs/` — этого не существует.** История чата не является источником истины.

## Правила ведения контекста между задачами

- **Перед задачей:** обновить `docs/STATUS.md`: задача, критерии приёмки, команды проверки.
- **Во время работы:** новые факты о бинарниках/форматах/поведении — в `docs/research/`
  с указанием источника (файл, хэш, RVA/offset, инструмент).
- **После задачи:** обновить `docs/STATUS.md` (что сделано, чем проверено, что дальше),
  `docs/PROJECT.md` (статус подпроекта), при необходимости `docs/DECISIONS.md`.
- **Одна задача = один подпроект** из `PROJECT.md`. Не смешивать подпроекты в одной задаче.
- **Definition of Done:** код + тесты + реально выполненные команды проверки (с выводом) +
  обновлённые документы. Без доказательств задача не считается выполненной.
- Не оставлять «TBD/TODO» в spec: всё нерешённое — в `STATUS.md` → Open Questions.

## Рабочий протокол сессии (обязательно)

1. **Старт сессии.** Прочитать `AGENTS.md` → `STATUS.md` → `PROJECT.md` → актуальные
   `specs/plans/research` → `DECISIONS.md`. Не начинать с кода и не полагаться на
   историю чата.
2. **Новый подпроект/фича:** `brainstorming` → spec (`docs/specs/…-design.md`) →
   одобрение пользователя → plan (`docs/plans/…`) → исполнение по задачам.
   Одна задача = один подпроект; не смешивать.
3. **Перед задачей:** запись в `STATUS.md` — задача, критерии приёмки, команды проверки.
   Убедиться, что spec/plan существуют и не противоречат `DECISIONS.md`.
4. **Паритет с оригиналом:** поведение/форматы — только из `Server.dll`/`Client.dll`/
   `GoldenLand.exe` (Ghidra/дизассемблер) или чтения памяти запущенной игры.
   Факты — в `research` с файлом, SHA-256, RVA/offset, инструментом и наблюдением.
   Сетки/таблицы сверять на полное совпадение (0/N), не «на глаз».
5. **Код:** слои только вниз; SDL только в `platform/app/render/ui/tools`; без
   комментариев без необходимости; TDD (сначала падающий тест).
6. **Проверка:** собрать и прогнать полный `ctest` с `GL_GAME_DIR`; для реальных
   данных — соответствующие real-тесты. Не заявлять успех без вывода команд.
7. **Ревью:** каждая задача проходит отдельного reviewer (spec + quality).
   Critical/Important — fix loop до чистого ревью; Minors — в ledger/`STATUS`.
8. **GUI-гейты:** интерактивные проверки запускает пользователь; агент не
   подтверждает manual pass.
9. **Финиш задачи/сессии:** обновить `STATUS` (сделано/проверено/дальше),
   `PROJECT`, `research`, при необходимости `DECISIONS`; commit; push — по указанию.
   Handoff в docs должен содержать точные адреса/функции и следующий шаг, чтобы
   новая сессия продолжила без истории чата.
10. **Документы:** UTF-8 без BOM. Не писать markdown через PowerShell here-string/
    `Set-Content` (были NUL-байты и литеральные `\n`); использовать `edit`/`write`,
    после правок проверять `nul=0` и отсутствие артефактов `\n`.
11. **Инструменты:** PATH тулчейна из раздела «Команды»; Ghidra headless — там же.
    Запущенный `glgame.exe` блокирует пересборку — закрывать игру перед build.
12. **Тупик/BLOCKED:** остановиться, зафиксировать в `STATUS`/research факты,
    что проверено и варианты; не подгонять поведение и не ослаблять тесты.

## Технические правила

- Язык: **C++20**. Сборка: **CMake ≥ 3.20 + Ninja**. Графика/ввод/аудио: **SDL2**.
  Сжатие: **miniz**. Изображения: **stb_image**. Тесты: **doctest**. Форматирование: `.clang-format`.
- Слои и зависимости — только «вниз»:
  `platform` → `app` → `game`/`render`/`ui`/`audio` → `script`/`core` → `assets`.
  `assets` не зависит от SDL и ОС (только стандартная библиотека + miniz/stb).
- Оригинальная архитектура клиент-серверная. В одиночной игре клиент и сервер работают
  в одном процессе, но за чёткой границей (`ServerCore` / `ClientCore`), чтобы не потерять
  возможность мультиплеера в будущем.
- Данные: только чтение оригинальных файлов игры из каталога, указанного пользователем.
  **Ассеты игры не коммитить и не распространять.**
- Кодировки: внутри данных — cp1251/ASCII; на границе API — UTF-8.
- Пути в виртуальной ФС — регистронезависимые, разделители нормализуются.
- **DRM:** не использовать `protect.dll`/StarForce и не обходить защиту. Порт не запускает
  оригинальные бинарники; он читает только файлы данных.
- Логирование: `gl::log` с уровнями (`debug/info/warning/error`), без секретов.
- Имена: типы — `PascalCase`, функции/переменные — `snake_case`, файлы — `snake_case`.
- Не добавлять комментарии в код без необходимости.

## Оригинал — источник истины

- Любое поведение (движение, коллизии, AI, формулы, порядок операций, лимиты)
  считается заданным только после извлечения из оригинала: `Server.dll`,
  `Client.dll`, `GoldenLand.exe` (дизассемблер/декомпилятор) или чтение памяти
  запущенной игры. «Правдоподобная» реализация запрещена.
- Факты фиксируются в `docs/research/` с указанием файла, SHA-256, RVA/offset,
  инструмента и наблюдаемого результата. Отклонения — только через
  `docs/DECISIONS.md`.
- Сетки/таблицы, снятые из памяти, проверяются на полное совпадение (например,
  `0/N` расхождений на реальном уровне), а не на «похожесть».
- Перед приёмкой подпроекта обязательна сверка с оригиналом: тест или ручной гейт
  должен подтверждать совпадение поведения, а не только работоспособность.
- Периодически проводится **аудит паритета** уже принятых подпроектов (P0…P4b2):
  для каждого пункта — есть ли подтверждение из оригинала; расхождения
  заводятся в `docs/STATUS.md` как отдельные задачи.

## Команды (обновлять по мере появления)

```powershell
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug
cmake --build build
ctest --test-dir build --output-on-failure
# Тулчейн (обязателен для сборки/тестов в этой сессии):
$tools="I:\goldenland2dec\.local\toolchains"
$env:PATH="$tools\llvm-mingw-20261006-ucrt-x86_64\bin;$tools\ninja;$tools\cmake\cmake-4.4.4-windows-x86_64\bin;$env:PATH"
$env:GL_GAME_DIR="I:\Games\Златогорье-2"   # без него real-тесты skip (exit 77)
# Запущенный glgame.exe блокирует линковку (Permission denied) — закрыть игру.
build\bin\glpak.exe info "I:\Games\Златогорье-2"
build\bin\glview.exe --game-dir "I:\Games\Златогорье-2" --level l1_1

# Ghidra headless (static reverse; уже лежит в .local/toolchains)
$env:JAVA_HOME="$PWD\.local\toolchains\jdk-21.0.12.1+1"
$proj="$env:TEMP\ghidra_proj"
& .local\toolchains\ghidra_12.1.4_PUBLIC\support\analyzeHeadless.bat `
  $proj glclient -import "I:\Games\Златогорье-2\Client.dll" -overwrite
& .local\toolchains\ghidra_12.1.4_PUBLIC\support\analyzeHeadless.bat `
  $proj glclient -process Client.dll -noanalysis `
  -scriptPath "$env:TEMP" -postScript "DecompileAt.java"
```

## Запрещено

- Коммитить данные игры, ключи, DRM-обходы.
- Коммитить без явной просьбы пользователя.
- Менять архитектурные решения без записи в `docs/DECISIONS.md`.
- Начинать реализацию без утверждённого spec/plan для текущего подпроекта.
