# Parity Matrix & Decomp Reference — Phase 0 (design)

Дата: 2026-11-05. Статус: approved (пользователь, 2026-11-05).

## 1. Цель

Создать измеримую основу полной реконструкции логики «Златогорья 2» в
переносимый C++20/SDL2: матрицу покрытия и машинно-сгенерированный
декомпил-корпус, чтобы у каждой подсистемы было доказательство из оригинала
и явный статус.

Phase 0 не меняет поведение порта и не исправляет найденные дефекты. Она
фиксирует текущее состояние и готовит инструменты для последующих фаз.

## 2. Контекст и решение

- Результат проекта — современный C++20/SDL2 под Android, а не сборка
  VC6. Байт-в-байт совпадение с оригинальными бинарниками не используется:
  современный компилятор всё равно генерирует другой код.
- Вместо SHA-256-гейта паритет подтверждается поведенческими оракулами:
  live-чтение памяти, hook-трассы, детерминированные сценарии
  «оригинал vs порт», пиксельные диффы, save round-trip и real-data тесты.
- Полнота контролируется матрицей: `verified / partial / missing /
  contradicted`, где каждая строка содержит доказательство или явный пробел.
- Декомпил-корпус — справочный материал для переписывания в переносимый
  C++, а не промежуточная собираемая сборка.

## 3. Scope

- `docs/research/parity-matrix.md` — матрица покрытия (committed).
- `docs/research/decomp-index.md` — индекс корпуса и команды выгрузки
  (committed).
- `.local/decomp/<binary>/` — сгенерированный корпус (ignored, не коммитится).
- `tools/ghidra/ExportDecomp.java` — headless-скрипт выгрузки.
- Обновления `docs/STATUS.md` и `docs/DECISIONS.md`.

## 4. Non-goals

- Исправление дефектов, найденных матрицей (отдельные spec/plan).
- Полная выгрузка `Client.dll` и `GoldenLand.exe` в Phase 0: выгружается
  только `Server.dll` как ядро логики; остальные — по мере фаз.
- Matching-decompilation, VC6, байт-идентичная сборка.
- Коммит сгенерированного псевдокода: корпус производен от бинарников и
  остаётся вне репозитория.

## 5. Статусы матрицы

- `verified` — утверждение подтверждено оригиналом (RVA/offset/live-память)
  или точным real-data прогоном, который пинит именно это утверждение.
- `partial` — данные/формат доказаны, но семантика взята из вторичного
  источника (редактор, плагин, README) либо тест не пинит заявленный count.
- `unverified` — evidence из оригинала нет; реализация — выбор порта,
  предположение или вторичный источник.
- `missing` — поведение не реализовано.
- `contradicted` — реализация противоречит подтверждённому факту или
  содержит воспроизводимый дефект.
- `superseded` — строка устарела и заменена новой; ссылка на замену
  обязательна.

Правило разрешения противоречий: evidence из оригинала важнее документации
порта; расхождение фиксируется как `contradicted` и отдельная задача.

## 6. Формат матрицы

Колонки:

`ID | Подсистема | Пункт | Реализация | Evidence | Статус | Пробел/задача | Источник`

- ID продолжает существующие: `P0-*`, `P1-*`, `P2-*`, `P3-*`,
  `P4a-*`, `P4b-*`, `P4b2-*` (префиксы вместо `A*/B*/C*`, чтобы не
  конфликтовать с backlog-задачами A1–A8), `P4d-*`, `A8-*`, `P5a-*`,
  `P5b1-*`.
- Одна строка — одно проверяемое утверждение.
- Evidence: путь к research/spec, RVA, имя теста, live-замер. «Работает» и
  «похоже» доказательством не считаются.
- Если более позднее решение отменяет строку аудита (A1–A6, A5/A6 и т.п.),
  строка получает `superseded` со ссылкой на актуальную.

## 7. Декомпил-корпус

- Инструмент: Ghidra 12.1.4 headless, JDK 21 (пути — из `AGENTS.md`).
- Для каждого бинарника:
  - `functions.csv`: RVA, размер, имя, признак thunk, число вызовов;
  - `decompiled.c`: заголовок функции + псевдокод C для всех функций;
  - `meta.txt`: SHA-256 бинарника, дата, команда, версия Ghidra.
- Путь: `.local/decomp/<binary>/` (gitignored).
- В Phase 0 выгружается только `Server.dll`; `Client.dll` и
  `GoldenLand.exe` — в следующих фазах.
- Скрипт идемпотентен: повторный прогон перезаписывает каталог.

## 8. Критерии приёмки Phase 0

1. `parity-matrix.md` содержит все строки аудитов P0/P1, P2/P3, P4a/P4b/
   P4b2 плюс P4d, A8, P5a, P5b1; у каждой строки есть статус и evidence.
2. В матрице есть сводка counts по статусам и список приоритетных пробелов.
3. `decomp-index.md` содержит SHA-256 `Server.dll`, число функций, дату и
   точную команду выгрузки.
4. Корпус `.local/decomp/server/` существует, `functions.csv` непуст,
   `decompiled.c` содержит псевдокод, а не только заголовки.
5. Документы — UTF-8 без BOM, без NUL-байтов и литеральных `\n`.
6. Код порта не изменён; `ctest` для Phase 0 не требуется.

## 9. Риски

- Псевдокод Ghidra может быть неверным: матрица хранит provenance, а не
  доверие к декомпилятору.
- Объём корпуса и правовой статус производного текста: корпус остаётся
  локальным, в git попадают только индекс и скрипт.
- Статусы могут быть субъективными: критерии из §5 и правило evidence
  важнее оценки.
