# A8-parity — cell mask occlusion (design)

Дата: 2026-11-03. Статус: реализовано; automated acceptance passed, manual gate OPEN.

## 1. Цель

Заменить приближение A8 («маска перекрывает всё, что выше baseline
`mask.y+height`») на engine-модель `ApplyCellMask`: перекрытие определяется
данными клетки (`LVL tile.mask`) и правилом `Client.dll FUN_1202bc54`, а не
baseline всего изображения маски.

Проблемы, которые это закрывает:

- hero у двери/стены перекрывается зданием, хотя стоит на клетке, которая не
  должна маскироваться (P4d manual gate);
- тень/тело стражника у ворот обрезаются «криво» там, где baseline режет
  часть спрайта;
- часть hero-тени при анимации исчезает у стен по той же причине.

## 2. Установленные факты (источник истины)

- `Client.dll 0x1202BC54` (`ApplyCellMask`) вызывается для каждой клетки
  персонажа; результат — набор id масок по колонкам клетки, которые затем
  используются рендером (`FUN_1202F17C`, `+0x839C`/`+0x838C`).
- `renderer+0x8344` — сетка записей 0x28 байт на клетку; в ней 4 subcell
  записи: flags в `+0x00..0x0C`, `mask_id` в `+0x10..0x1C`.
- `ApplyCellMask` проверяет непрерывность `mask_id` вправо и вниз по
  subcell-записям и учитывает биты flags; применяет маску только при
  выполнении условий. Точная семантика битов извлекается в Research-задаче
  плана и фиксируется с RVA/дампом до кода.
- Сетка `+0x8344` строится не в `Client.dll`: `FUN_1202E370` получает её
  через host-объект `DAT_12110F3C` (vtable `+0x5C`, размеры — `+0x44`).
  Значит источник данных — LVL/host, а не Client.
- `LVL LvlTile.mask` — **0-based индекс в списке `BLK_MDSC`**, `0xFFFF` =
  нет маски. Проверено на `l1_1`: клетка героя `(180,24)` имеет индекс 6,
  `lvl.masks[6].number == 8`; mask 8 — здание с `x=2054,y=-17`, bottom=218.
  Это объясняет текущее ложное перекрытие hero в двери.
- Размер «клетки» рендера — 24×18 px (2×2 тайла 12×9); `tile.mask` задан на
  тайл (subcell). Маска привязана к BLK_MDSC записи `number,x,y`; картинка
  `mask_<number>.csx`, alpha=0 — перекрывающий foreground (A8/D-037).

## 3. Требуемое поведение

Для каждого персонажа (hero и NPC), находящегося в клетке `C`:

1. По `C` и её subcell берётся `tile.mask` индекс. `0xFFFF` — маска не
   применяется.
2. Если индекс валиден и соответствующая маска загружена, решение
   «применять/не применять» и набор колонок клетки, к которым применяется
   маска, вычисляются **точно как `FUN_1202BC54`** по данным
   `tile.mask`/BLK_MDSC. Baseline `mask.y+height` больше не используется как
   критерий перекрытия.
3. Для применённой маски рендер перекрывает только её выбранные колонки
   (foreground alpha=0), сохраняя порядок Y-sort (D-036). Остальные маски
   рисуются как раньше.
4. Тени и тела используют одно и то же решение о маске (engine применяет
   маску к проходам тени и тела одинаково).

Поведение считается заданным только после фиксации семантики в
`docs/research/a8-mask-parity.md` (RVA, биты, формулы, live-дамп). До этого
шага код не менять.

## 4. Архитектура

```
LVL parse (tile.mask уже есть)
        │
        ▼
Level::tile_masks (grid indices) + mask_index→number
        │
        ▼
game: mask_selection (pure, engine rule)  ──► per-cell mask decisions
        │
        ▼
app: LevelScreen — маски в Y-sort только по выбранным клеткам/колонкам
```

- `gl_assets::LvlTile::mask` уже парсится; изменения в assets не нужны,
  кроме тестов на значения.
- `gl_game::Level` получает `TileMaskGrid` (width×height индексов) и
  `mask_numbers` (index→BLK_MDSC number), заполняемые в `load_level`.
- `gl_game::mask_selection` — SDL-free чистая функция/структура,
  реализующая `FUN_1202BC54`; тестируется на synthetic grid.
- `gl_app::LevelScreen` заменяет `MaskOverlay.baseline/center_x`-merge на
  результат `mask_selection`; интерфейс масок (`number,x,y,image`) остаётся.

## 5. Scope

Входит:

- `LVL tile.mask` → `Level::tile_masks`, включая mapping index→number.
- Точная реализация `ApplyCellMask` для одной клетки персонажа (текущая
  модель occupancy порта — одна клетка).
- Применение масок к hero и NPC (тело и тень), Y-sort без baseline-merge.
- Synthetic + real тесты; screenshot-тесты; замена A8-теста на
  engine-модель.
- Документация: research, spec, plan, STATUS/DECISIONS.

Не входит:

- Multi-cell/size-based occupancy (большие спрайты, если engine использует
  несколько клеток) — отдельная задача; текущие hero/NPC занимают одну
  клетку.
- `r_masks_mode`, `r_masked_show`, alt-маски, рантайм-изменения масок
  дверями/скриптами.
- Изменение PAD/wear геометрии и P4d-рендера.
- Маски статиков/LAO.

## 6. Ошибки и деградация

- `tile.mask` вне диапазона `BLK_MDSC` или маска не загружена → warning
  один раз на индекс, маска не применяется (не падать).
- Отсутствующий `BLK_MDSC`/LVL → существующая ошибка загрузки уровня.
- `mask_selection` не бросает исключений; некорректные индексы → «нет
  маски» + warning на уровне загрузки.

## 7. Тесты и приёмка

1. Research: в `docs/research/a8-mask-parity.md` записаны RVA
   (`FUN_1202BC54`, `FUN_1202F17C`, `FUN_1202E370`), точные биты/сканы,
   размер массива колонок, live-дамп `tile.mask` и решения для клетки hero
   `(180,24)` и стража у ворот; SHA-256 бинарников.
2. Synthetic: `TileMaskGrid` с индексами; клетка без маски; клетка с
   маской на краю региона (не применяется по engine-правилу); внутренняя
   клетка (применяется); mapping index→number; битые индексы.
3. Real `l1_1`: для клеток с известными индексами решения совпадают с
   research-дампом; маски применяются только к выбранным клеткам.
4. Visual: `glview`/`glgame` screenshot-тесты — hero у двери и стражник у
   ворот совпадают с оригиналом (эталонный скриншот/ручной гейт); нет
   ложного перекрытия тела/тени.
5. Полный `ctest` с `GL_GAME_DIR` — 17/17.
6. Manual desktop gate: пользователь сравнивает с оригиналом в тех же
   точках; без него A8-parity не принят.

## 8. Риски

- Точная семантика битов `+0x00..0x0C` и колонок может потребовать live
  чтения памяти; debugger запрещён (D-004/анти-отладка), использовать
  `ReadProcessMemory`.
- Смена A8-модели может изменить кадры принятых A8-тестов; обновлять
  ожидания только вместе с research-доказательством, не подгонять.
- Multi-cell NPC: если research покажет, что движок использует несколько
  клеток, зафиксировать ограничение и вынести в отдельную задачу до
  реализации.

## 9. Definition of Done

- Research зафиксирован с адресами/дампом; baseline-merge удалён.
- Тесты 1–6 зелёные; полный `ctest` и manual gate пройдены.
- `STATUS`/`PROJECT`/`DECISIONS`/research обновлены; P4d manual gate можно
  закрывать после A8-parity (если других дефектов нет).
