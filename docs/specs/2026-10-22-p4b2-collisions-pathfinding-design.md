# P4b2: коллизии и pathfinding NPC — дизайн

## 1. Цель

NPC не проходят сквозь препятствия и друг друга: ходьба учитывает проходимость
тайлов уровня и строит обход, как в оригинале. Продолжение P4b (движение по
маршрутам) перед P4c.

## 2. Область

Входит:

- сетка проходимости из `relief` первого тайла чанка LVL (биты 8..11);
- прямая ходьба при свободной линии, иначе A*-обход (8 направлений);
- динамическая занятость NPC (обход друг друга);
- replan при блокировке; пауза и повтор, если пути нет;
- `--walkable-overlay` для визуальной сверки;
- тесты и документы.

Не входит: клик игрока → path (P4c), бит обзора `0x1000`, терраин-косты,
двери/динамические препятствия, pathfinding для боя/убегания.

## 3. Данные (подтверждено)

Подробности и RVA — `docs/research/p4b2-walkability-pathfinding.md`.

- Чанк LVL = 2×2 тайла; файл хранит чанки column-major: индекс
  `cx*chunk_height + cy`. Поле `mask` для движения не используется.
- Ключевое слово чанка — первая запись:
  `word = uint32(tile[0].relief) | (uint32(tile[0].sound)<<16)` (биты 8..11
  `tile[0].relief`). Для world-тайла `(x,y)`: `sub=(x&1)+2*(y&1)`;
  `blocked=(word & (0x100u<<sub))!=0`; `walkable=!blocked`.
- `l1_1`: 230×224 тайла; заблокировано **18028** из 51520.
- Сверка с live-памятью оригинала (`world+0x330`, getter `FUN_00426234`,
  vtable `0x484a00`) дала точное совпадение после загрузки; ~331 клетка
  меняется в рантайме дверями/скриптами и вне P4b2.
- Оригинал: прямая линия проверяется по клеткам; иначе Dijkstra-поле; занятые
  другими сущностями клетки исключаются (D-028).

## 4. Архитектура

```
assets: Level.walkable (WalkGrid)
game:   Pathfinder (A*, line-of-sight), LevelSimulation (obstacles, occupancy, replan)
app:    --walkable-overlay
```

### 4.1 `gl_assets` / `gl_game` — WalkGrid

```cpp
struct WalkGrid {
    std::int32_t width = 0, height = 0;   // тайлы
    std::vector<std::uint8_t> walkable;   // 1 = можно
    bool is_walkable(std::int32_t x, std::int32_t y) const;
};
```
`gl::game::Level` получает `WalkGrid walkable;`; `load_level` заполняет из
`LvlData::chunks` (пустой `LvlData` → сетка пустая, NPC не двигаются).

### 4.2 Pathfinder

```cpp
struct Tile { std::int32_t x = 0, y = 0; };
bool line_of_sight(const WalkGrid&, Tile from, Tile to,
                   const std::vector<std::uint8_t>& blocked);   // Брезенхэм
std::vector<Tile> find_path(const WalkGrid&, Tile from, Tile to,
                            const std::vector<std::uint8_t>& blocked);
```
- A* 8 направлений; стоимость шага 1 для всех направлений (диагональ = ортогональ,
  как 10 в оригинале); эвристика `h = max(dx,dy) + 0.375*min(dx,dy)`, вес **1.2**
  (`f = g + 1.2*h`).
- Диагональ разрешена без проверки ортогональных соседей — проверяется только
  клетка назначения.
- Ничьи по `f` разрешаются FIFO по порядку вставки (монотонный счётчик в ключе).
- `blocked` — массив занятости (1 = занято другим NPC); своя клетка не занята.
- Цель недостижима → пустой вектор.
- Границы сетки — всегда препятствие.

### 4.3 LevelSimulation

- Строит occupancy каждый тик только из текущих тайлов всех NPC; будущие и
  путевые клетки не резервируются (A6/D-034). После хода персонажа помечается
  только его текущий тайл, чтобы следующие в том же тике видели новую позицию.
  Освобождённая клетка внутри тика не очищается: до следующего `rebuild_occupancy`
  occupancy содержит текущие тайлы плюс только что занятый тайл.
- При выборе цели: `line_of_sight` → путь `{from, goal}` и движение по прямой
  к цели без промежуточных клеток-центров; иначе `find_path`, и персонаж идёт
  по waypoint-ам.
- Каждый тик проверяется клетка, в которую персонаж собирается войти: если она
  заблокирована или занята текущей позицией другого NPC — replan к той же цели.
  Собственная текущая клетка и собственная цель (`state.goal` при `has_goal`)
  из occupancy исключены для **всех** route-типов; это освобождение цели, а не
  резерв. Резервов цели/пути нет; к промежуточным центрам клеток при свободной
  линии не привязываемся.
- Достигнув waypoint, берёт следующий; очередь опустела — цель достигнута
  (пауза `delay_min..max`, как в P4b).
- Если пути нет — пауза `delay_min..max` и повтор выбора цели.
- `RANDOM*` выбирает только проходимые клетки; занятость при выборе не
  фильтруется (A3/D-032; остаточное расхождение C12 — цель исключена из
  occupancy для всех route-типов, A6 его не меняет).
- Детерминизм и фиксированный шаг 1/60 сохраняются; порядок NPC — порядок в
  `Level::persons`.

### 4.4 `gl_app`

- `--walkable-overlay` в `glview`/`glgame`: поверх уровня полупрозрачный красный
  по заблокированным тайлам (12×9 px), не влияет на обычный рендер.

## 5. Тесты

Unit:

- WalkGrid: синтетические чанки (биты 8..11 `relief[0]`, `sub`), column-major
  порядок чанков, границы; реальные `l1_1` — 230×224, 18028 заблокированных.
- `line_of_sight`: свободная линия, линия через стену, диагональ.
- A*: обход стены, путь по диагонали, недостижимая цель, occupancy (своя клетка
  свободна, чужая — препятствие).

Real (`GL_GAME_DIR`):

- `l1_1` 60 с: ни один NPC не оказывается в заблокированном тайле; два NPC не
  занимают один тайл одновременно; детерминизм двух прогонов.
- Маршрут track2/track4 проходится (NPC достигает waypoint-ов) — путь не пуст.

Screenshots:

- `--walkable-overlay` 1280×720: заблокированные тайлы совпадают с домами на
  фоне (визуально, ручной гейт); автотест — PNG отличается от обычного кадра.

## 6. Критерии готовности

1. NPC обходят препятствия и друг друга на `l1_1` (ручной гейт).
2. Нет входа в заблокированные тайлы и наложения NPC (тесты).
3. Детерминизм сохранён; P4b-тесты зелёные.
4. `gl_game`/`gl_assets` SDL-free; полный `ctest` зелёный.
5. `--walkable-overlay` позволяет сверить маски с фоном.

## 7. Риски

- Ложные препятствия из-за неверного порядка тайлов в чанке — снимается overlay
  и реальным тестом (0 заходов в блок).
- Взаимные блокировки NPC в узких проходах — ограничение по времени ожидания
  (пауза и повтор выбора), без дедлоков.
- Производительность A* на 230×224 при 6 NPC — приемлемо; кэш не нужен.

## 8. Отложено

Клик игрока → path (P4c), бит `0x1000`, терраин-косты, динамические препятствия,
Y-сортировка.
