## Узлы и исполнение (`CsExecutor::next`)

Узел (`index`, `opcode`, `a`,`b`,`c`,`d`, `value`, `text`, `args[9]`):

- `0 ||`, `1 ^^`, `2 &&` — логические. `a`,`b` — индексы подвыражений; вычисляются
  **оба** (без short-circuit), результат `int`; переход на `c` (истина) или `d` (ложь).
  `1 ^^` — логический xor истинности операндов; строки для него запрещены.
- `6..11` — сравнения (`!=`,`==`,`>=`,`<=`,`>`,`<`). `a`,`b` — значения;
  переход на `c`/`d`.
- `14..18` — арифметика (`+ - * / %`). Возвращает значение, не управляет потоком.
- `3..5` (`| ^ &`), `12/13` (`<< >>`) — битовые операции/сдвиги над 32-битными
  целыми (double приводится к `int32`, строки запрещены); сдвиг вне `0..31` —
  ошибка исполнения. `19 ~`, `20 !` — унарные, операнд в `a`; строки запрещены.
- `21 num_var`, `24 num` — числовой литерал (`f64 value`); `22 str`, `23 str_var` —
  строка (`text`, cp1251→UTF-8) / имя строковой переменной.
- `48 func` — `value` = id функции (`f64`), `args` — индексы узлов-аргументов до `-1`;
  `c`/`d` в исполнении не используются.
- `49 jmp` — переход на `c`; `d == -1` — конец ветки: `wait_user`, если в текущем
  прогоне уже был `D_Say`, иначе `end`.
- `50 assign` — `a` = индекс узла `str_var` (приёмник), `b` = индекс источника,
  `d` = следующий узел.

Стартовое состояние: `pc = 0`, статус `start`. Каждый `step()` выполняет один
управляющий узел (логика/сравнение/jmp/assign); выражения-операнды вычисляются
рекурсивно. Счётчик шагов инкрементируется на каждом вызове; при достижении лимита
статус `infinity`.

В порту `ScriptVm::failed()` отделяет ошибки исполнения от нормального завершения:
флаг ставится для неподдержанного top-level/expression опкода, недопустимого индекса,
ошибок типов/вычислений (строки в арифметике/битовых/унарных, деление/модуль на ноль,
сравнение строки с числом, rel-сравнение строк), исчерпания бюджета вычисления и лимита
шагов. `end`/`wait_user` из нормального потока оставляют флаг false.

Ошибки «липкие»: `record_error` сразу выставляет `failed()` и останавливает текущий
`step()` (статус `end`, возврат false), поэтому соседние операнды после ошибки не
вычисляются, а повторные ошибки не пишутся в лог. `restart(true/false)` сбрасывает
флаг; `user_input` его не сбрасывает (в отличие от прежней реализации). Бюджет
`kEvalBudget = 100'000` вызовов `eval` на один `step()` ограничивает циклические и
разделяемые графы выражений, для которых одного `kMaxEvalDepth` недостаточно.

## Приведение типов

- Сравнение: правый литерал приводится к типу левого операнда
  (`(T)node.value`); строки поддерживают только `==`/`!=`. Сравнение строки с числом
  и rel-сравнение строк считаются ошибкой исполнения (`failed()`).
- Арифметика: правый литерал приводится к типу левого; операнды-переменные сохраняют
  свои типы, результат — по обычным арифметическим преобразованиям C++
  (`int32`/`uint32`/`double`). Строки в арифметике запрещены, деление/модуль на ноль —
  ошибка исполнения (`failed()`), результат подставляется `0`.
- `assign`: RHS (литерал, переменная, `func`, арифметика) приводится к текущему типу
  переменной-приёмника (`int32`, `uint32`, `double`, `string`). Это исправляет обрезку
  `float`-приёмника до `int` и сатурацию `DWORD`; число → строка даёт десятичное
  представление, строка → число — ошибка исполнения. В редакторе (`CsExecutor`) прямые числовые литералы всегда
  сохранялись как `(int)value` с TODO на корректное приведение.

## Функции

- `D_Say` (`0x1000004`), `D_Answer` (`0x1000006`) — записываются в список диалога
  в порядке вызова; host не вызывается; результат `0`.
- `D_CloseDialog` (`0x1000005`) — завершает исполнение (`end`, D-023).
- `Exit` (`0x1000000`), `Signal` (`0x1000001`), `Console` (`0x1000002`),
  `Cmd` (`0x1000003`) — передаются в `ScriptHost::call`; `DefaultScriptHost` логирует
  их на info и возвращает `0`. VM их не перехватывает, поэтому хост можно переопределить.
- Остальные id — `ScriptHost::call(id, args)`; значения аргументов вычисляются из
  узлов (литералы, переменные, вложенные выражения). `DefaultScriptHost` различает
  известные id (`cs_function_is_known`) и неизвестные: debug vs warning.

## Диалоговый flow

- В редакторе `dialogsData()` при `wait_user` возвращает фиксированный массив
  `[sayValue, answerValue...]` до 11 элементов, а вне `wait_user`/без `D_Say` — `{-1}`.
  В порту `dialogs_data()` возвращает `std::vector<uint32_t>`: первый элемент — id
  фразы первого `D_Say`, далее id всех `D_Answer` в порядке вызова. Если на странице
  несколько `D_Say`, используется только первый — как `m_dialogFuncs.front()` в
  редакторе. Вне `wait_user` вектор пуст; `answers_count()` =
  `dialogs_data().size() - 1` (0 при пустом векторе).
- `user_input(answer)` в порту принимает **индекс ответа с нуля** (0 — первый
  `D_Answer`), проверяет его по записанным ответам и при выходе за границы пишет
  warning, возвращает `false`, не меняя состояние. При успехе возвращает `true`,
  `LastPhrase = id D_Say`,
  `LastAnswer = id выбранного D_Answer` (оба `uint32`), записанные вызовы очищаются,
  `pc = 0`, статус `restart`; счётчик шагов не сбрасывается (как в редакторе).
  Отличие от редактора: его `userInput(uint8_t)` индексирует `m_dialogFuncs` целиком
  (0 — это `D_Say`) и проверяет `answer >= m_dialogFuncs.size()`, поэтому ответ 0
  выбирает `D_Say`; порт использует нумерацию ответов, заданную spec/brief.
- `D_CloseDialog` в P3a сразу переводит исполнение в `end` (D-023).
- `DefaultScriptHost` — заглушка для нативных функций: `RS_GetPersonParameterI` → 0;
  `Exit`/`Signal`/`Console`/`Cmd` → 0 + info; известные имена → 0 + debug; неизвестный
  id → 0 + warning. Тесты могут наследовать его и переопределять `call`.

## Переменные и restart

`CsExecutor::readScriptVariables` обходит все узлы `23 str_var` и копирует значения
одноимённых глобальных переменных; отсутствующие — warning. `restart(true)` повторяет
этот импорт, `restart(false)` сохраняет значения и сбрасывает `LastPhrase`/`LastAnswer`
в `uint32 0`. `restart` также обнуляет счётчик, `pc`, статус и список функций диалога.

## Глобальные переменные (`CsExecutor::readGlobalVariables`)

Строки `type name value`, `type ∈ {int, DWORD, float, string}`, комментарии `//`,
строки без трёх токенов пропускаются с warning. Строковое значение — в кавычках.
`gl_script::parse_globals` дополнительно декодирует cp1251→UTF-8, пропускает
неизвестные типы (в редакторе неизвестный тип оставлял default `int32 0`), игнорирует
UTF-8 BOM в начале файла и предупреждает о незакрытой кавычке (значение при этом
принимается без закрывающей кавычки).

- Во всех 555 файлах последний узел — `24 num` (данные); завершение всегда через

  (240 узлов, 784 глобальные переменные) → `wait_user` за 43 шага; `LastPhrase`

## Инструменты (Tasks 4–5)

- `glpak disasm-cs <game_dir> --file <path.cs> [--out <txt>]` читает файл через
  `GameVfs`, парсит `parse_cs` и печатает один узел на строку:
  `index: opcode | поля | value/text | funcName(args)`. Без `--out` — stdout, с `--out` —
  UTF-8 файл; строки экранируются (`\"`, `\\n`, `\\xHH`). Коды выхода: 0/1/2/3.
- `glscript --game-dir <dir> [--globals <path>] --file <path> [--run] [--answer N]`
  читает CS и globals через VFS (по умолчанию `scripts/dialogs_special/zlato_vars.scr`),
  исполняет до `wait_user`/`end`/`infinity` и печатает `status`, `steps`, id из
  `dialogs_data()` и `answers_count()`. `--answer N` повторяемый, нумерация ответов
  с нуля; после успешного ответа исполнение продолжается до следующего останова.
  `--answer` без `--run` или ответ вне диапазона — exit 1; ошибка VM (`failed()`) —
  exit 3.
- Приёмка 2026-10-21: `ctest` с `GL_GAME_DIR` — 11/11 passed, 573.09 s; real-data
  `parsed=555 failures=0 nodes=338977`. `demon.d1.age.cs` → disasm 5353 B / 240 lines;
  `glscript --run` → `wait_user`, 43 steps, dialogs `2684 2686 2696`, 2 answers;
  `--answer 0` → следующий `wait_user`, 84 steps, dialogs `2719 1529 2721`, 2 answers.

## Ограничения P3a

- `^^` (1), битовые (3..5, 12/13) и унарные (19/20) реализованы по именам
  `CsOpcodes.cpp`; в 555 реальных `.cs` они не встречаются, поэтому проверены только
  синтетическими тестами.
- Полный набор native-функций и диалоговый UI — P3c/P7.
- Лимит шагов 10 000 000 (в редакторе 10 000) — D-023; `infinity` также даёт `failed()`.
  Дополнительно действует бюджет 100 000 вызовов `eval` на `step()`.
