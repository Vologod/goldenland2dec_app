# P4b: движение NPC — статический реверс `Server.dll`

`E3E0A262B1A60DE687523465AD5A36E8` (см. `00-game-build.md`). PE x64, image base
`0x140000000`. Инструмент: Ghidra 12.1.4 (headless), декомпилятор. RVA ниже — это
виртуальные адреса, т.е. RVA = адрес − `0x140000000`.

## Разбор SEF

`FUN_1401edc4` (RVA `0x1edc4`) — секция `persons:`. Поля пишутся в объект Person:

| Смещение | Поле |
|---|---|
| `+0x40` | `literary_name` |
| `+0x44` | тип literary name |
| `+0x5f8/+0x5fc` | `position` (тайлы), spawn |
| `+0x151c` | `route_type` (enum выше) |
| `+0x1520` | `radius` |
| `+0x1524` | `route` (имя `cell_group`) |
| `+0x2668/+0x266c` | `delay_min` / `delay_max` |

`FUN_140222d0` (RVA `0x222d0`) переводит тайлы в пиксели:
`px = tile_x * 12 + 6`, `py = tile_y * 9 + 4`; эти же значения — «центр» клетки.
Позиция также хранится как float (`+0x4fc/+0x500`, `+0x628/+0x62c`) и как тайлы
(`+0x604/+0x608`).

## Выбор следующей цели

`FUN_1401c93c` (RVA `0x1c93c`), «Next moved»:

- Маршрут: указатель `+0x162c`, индекс `+0x1630`, количество клеток `+0x190`
  относительно ресурса маршрута.
- `MOVED` (2): если `index >= count`, `index = 0`; цель = `route[index]`; затем
  `index++`. Движение по кругу.
- `MOVED_FLIP` (3): если `index < 0 || index >= count`, `index = 0`; цель =
  `route[index]`; затем `index += (rand(0.5) ? 1 : -1)`, где `rand(0.5)` —
  `FUN_14006288` (50 %). Случайное блуждание вдоль маршрута.
- `RANDOM_RADIUS` (4): цель = случайная точка вокруг **spawn** (`+0x5f8/+0x5fc`).
- `RANDOM` (5): цель = случайная точка вокруг **текущей** позиции (`+0x604/+0x608`).
- `STAY` (0): если позиция смещена от spawn, идёт назад к spawn; иначе стоит.
- `STAY_ROTATE` (1): поворот на месте; в `l1_1` не встречается.

Случайная точка — `FUN_1401c2a0` (RVA `0x1c2a0`): `r = +0x1520`, при `r == 0`
берётся 13; `dx,dy = rand(-r..r)` (в тайлах); повтор до проходимой клетки
(`FUN_1401c334`, мир + маска `0x100`). В P4b проходимость не моделируется — только
границы карты и ограниченное число попыток.

## Пауза после прибытия

`FUN_1401c378` (RVA `0x1c378`):

1. Если `now < wait_until (+0x1634)` — ждать.
2. Иначе, если флаг ожидания (`+0x1638`) не выставлен: `d = rand(delay_min..delay_max)`
   (`FUN_140061e4`, inclusive-ish CRT `rand`).
   - `d < 500` → паузы нет, сразу следующая цель;
   - иначе `wait_until = now + d`, флаг = 1, ждать.
3. По истечении — сбросить флаг и продолжить.

Время `now` — `DAT_14088e1c`, миллисекунды.

## Прибытие и скорость

`FUN_14021754` (RVA `0x21754`) и `FUN_14020444` (RVA `0x20444`):

- Цель — центр клетки в пикселях; прибытие, когда `|dx| < 4` и `|dy| < 4` px.
- `FUN_1401fef8` (RVA `0x1fef8`) записывает скорость в `+0x584/+0x588` и модуль в
  `+0x158`.
- Скорость берётся из выбранной анимации `_go`: поля `+8/+0xc` дескриптора
  соответствуют `movement_x/movement_y` PAD. Реальные значения `l1_1`:
  `6.0..6.916667` px и `5.0` px; `delay` `_go` = 85 мс.
- Диагональ: `fx² = dx²/(dx²+dy²)`,
  `speed = (1-fx²)*movement_y + fx²*movement_x`;
  `vx = dx/len * speed`, `vy = dy/len * speed`.
- Константы перевода: `1/12 = 0.0833333`, `1/9 = 0.1111111`.
- `_go` содержит 16 направлений. `FUN_1402085c` (RVA `0x2085c`) по знаку и
  абсолютным компонентам единичного вектора возвращает код 10..25; пороги:
  `0.2079`, `0.5878`, `0.8616`, `0.9863`.
- `FUN_14020e64` (RVA `0x20e64`) переводит 16 кодов в 8 направлений:
  `10→0`, `11..13→1`, `14→2`, `15..17→3`, `18→4`, `19..21→5`, `22→6`, `23..25→7`.
  Обратно `FUN_14020e14`: `0→10`, `1→12`, `2→14`, `3→16`, `4→18`, `5→20`,
  `6→22`, `7→24`.
- `FUN_1401fb1c` (RVA `0x1fb1c`) — строки SEF `UP, UP_LEFT, LEFT, DOWN_LEFT, DOWN,
  DOWN_RIGHT, RIGHT, UP_RIGHT` → 0..7 (совпадает с P4a).

## Частота обновления

`sv_fps` по умолчанию **35** (регистрация в `FUN_14003884`, RVA `0x3884`:
`0x23`), `sv_game_speed` — 0..4. Точная частота вызова обновления Person
(`FUN_14020260`, RVA `0x20260`) статически не закреплена (вызов виртуальный).
Принятое решение D-026: `movement_x/y` — пиксели **за кадр go-анимации**
(`delay` мс), т.е. `speed_px_s = movement * 1000 / delay`; в порте шаг 1/60 с.

## Что не подтверждено

- Точная формула `STAY_ROTATE` (тип 1) и `RANDOM` (тип 5) за пределами выбора цели.
- Влияние масок проходимости на маршруты (P4b не моделирует коллизии).
- Поведение при отсутствии `_go` (в `l1_1` у движущихся NPC анимация есть).
