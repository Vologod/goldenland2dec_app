# P4b2: проходимость и pathfinding — статический реверс

Источник: `I:\Games\Златогорье-2\Server.dll` (v1.3, SHA-256
`E3E0A262B1A60DE687523465AD5A36E8`), PE x64, image base `0x140000000`.
Инструмент: Ghidra 12.1.4 (headless). RVA = адрес − `0x140000000`.
Данные: `levels/lvl/l1_1.lvl` из `levels.pak`.

## Маски тайлов LVL

- Тайл: `u16 relief`, `u16 sound`, `u16 mask` (см. `formats.md`), по умолчанию
  `mask = 0xFFFF`.
- `l1_1.lvl`: 115×112 чанков = 230×224 тайла = 51520; различных масок 63.
  `0xFFFF` — 40999 тайлов; у остальных бит `0x100` снят. Итого **10521**
  заблокированный тайл (≈20 %). Проверено через `parse_lvl` 2026-10-22
  (`src/game/include/gl/game/walk_grid.hpp`, task P4b2-1); прежние 40997/10523
  были получены вычитанием из 51520 при разборе со смещением на 2 тайла.
- Мир (`DAT_14088e30`) отдаёт блокировку через виртуальный `+0x64(x, y, flag)`:
  ненулевое значение — клетка заблокирована для флага. Флаги: `0x100` — движение,
  `0x1000` — обзор. `+0x70(x, y)` — проверка границ; `+0x48(&w, &h)` — размер мира.
- Вывод: `is_walkable(x,y) = в границах && (tile.mask & 0x100) != 0`.

## Динамическая занятость

- `DAT_14088dac` — массив `int` по клеткам, инициализируется `-1` (пусто) в
  `FUN_14012b18` (RVA `0x12b18`). Установка/чтение: `FUN_14012cdc` (`0x12cdc`),
  `FUN_14012d00` (`0x12d00`), `FUN_14012d2c` (`0x12d2c`).
- При поиске пути клетки с `grid != -1` (кроме собственной) считаются занятыми
  (`FUN_14010d38`, `FUN_14015b48`), т.е. NPC обходят друг друга.

## Проверка ходьбы и поиск пути

- `FUN_1401c334` (RVA `0x1c334`) — «клетка проходима»: границы + `+0x64(...,0x100) == 0`.
- `FUN_1400fb1c` (RVA `0xfb1c`) — «клетка свободна для сущности»: `grid == -1` или
  `grid == self`, и `+0x64(...,0x1000) == 0`.
- `FUN_14012d4c` (RVA `0x12d4c`) — валидация прямой линии A→B: идёт по клеткам
  (Брезенхэм с дробным шагом) и возвращает 0 при первой заблокированной/занятой
  клетке.
- `FUN_14010d38` (RVA `0x10d38`) и `FUN_1400ffd4` (RVA `0xffd4`) — построение поля
  расстояний (Dijkstra/волна) по 8 направлениям от стартовой клетки; массив стоимостей
  `+0x14`, массив предков `+0x10` (пары клеток). Заблокированные и занятые клетки
  исключаются.
- `FUN_14015b48` (RVA `0x15b48`) — проверка соседней клетки при следовании пути.
- Прямая ходьба используется, если линия свободна; иначе строится путь и персонаж
  идёт по waypoint-ам (см. `FUN_14020444`/`FUN_14021754`, `p4b-person-movement.md`).

## Отклонения порта (D-028)

- Терраин-костов в данных нет; вместо Dijkstra с костами — A* с единичной стоимостью
  (диагональ √2), те же 8 направлений.
- Бит обзора `0x1000` не моделируется.
- Динамические препятствия (двери/триггеры) не входят в P4b2.
