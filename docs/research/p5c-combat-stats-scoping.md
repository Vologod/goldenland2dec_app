# P5c — combat/stats values for the character sheet (scoping research)

Дата: 2026-11-25. Статус: scoping (нужна экстракция формул; реализация не
начата).

## Зачем

Сейчас лист персонажа показывает `—` для state(не всё)/combat/resistance/
immunity и для навыков — значения данных не смоделированы. Оригинал
показывает реальные числа. Нужно воспроизвести.

## Что уже известно (из `FUN_120661cc`, RVA `0x661cc`)

Значения рисуются геттерами `Client.dll`; это **вычисления над полями
персоны**, а не готовые поля сейва:

- `FUN_1201fb10` (RVA `0x1fb10`): уровень — пороги по значению из
  `FUN_1201fbd4` (`100`, затем `+50` на уровень: `i*step+step <= exp`).
- `FUN_1201fb5c` (RVA `0x1fb5c`): использует поля `this+4`, `this+8`,
  `this+0x6c` и лог-функцию `FUN_1201b1c4(x, 0x1c)` (точка возврата
  clamp'ится полями) — нелинейная формула.
- Значит для паритета нужны и формулы геттеров, и **структура статов**
  персоны (её заполняет `Server.dll`, SHA-256
  `418E256063748F2E90DB35AE7C6ABE6EAC401FB86908CB5F27EBF565A21CC837`).

## Наблюдение по вычислимости

Часть полей — прямые (жизнь/энергия/max), часть — формулы (уровень,
слава, урон, сопротивления). Формулы комбинируют атрибуты + надетую
экипировку + навыки; порт уже имеет `PersonRuntime`, `ItemCatalog`
(`weight_x10`, ITM effects), `HeroInventory` (equipped) — входы есть.

## Предлагаемая декомпозиция (инкременты)

1. **P5c1 — stat-структура + простые поля**: найти в `Server.dll`
   расчёт статов персоны (layout/поля), вывести уровень/опыт/жизнь/
   энергию/AP/славу; отрисовать в листе. Наименьший риск.
2. **P5c2 — броня/вес**: `Класс брони` и `Вес` (агрегаты экипировки +
   capacity) — `FUN_1201f7a0`/`FUN_1201e92c`.
3. **P5c3 — урон**: 6 строк урона по типам (min–max) —
   `FUN_1201f5e0/458/2d0/134/ef98/edfc`.
4. **P5c4 — точность/крит**: `FUN_1201e660`/`FUN_1201e384`.
5. **P5c5 — сопротивления**: 12 строк — `FUN_1201d244…1cc8c`.
6. **P5c6 — иммунитеты**: 6 строк — `FUN_1201ff00…1fe58`.
7. **P5c7 — значения навыков/очки**: `FUN_1201fab4`/`1fc34`.

Каждый инкремент: research формулы → spec → реализация → real-тест
(сверка с сохранением/скриншотом).

## P5c2 — экстракция (класс брони / вес), 2026-11-25

`FUN_1201f7a0` (броня, RVA `0x1f7a0`) → int 0..50:
- item = `vtable[+0x18](person, -1)`; `iVar3 = vtable[+0x28](item)`;
  `iVar4 = FUN_120204e8(this,person)`; `iVar5 = FUN_1201fab4(...,6)`;
  `f = (iVar4+iVar5)*DAT_12123f14`;
  если `iVar3!=0`: `iVar4' = vtable[+0x2c](item)`;
  `f += (iVar4'*DAT_12123f0c + DAT_12123f10) *
        (item+0x24 + table(DAT_12123f18, sign(item+0x24)))`;
  `f = FUN_1201b1c4(f, 0x1d)`;
  если `DAT_12106bc0+0x8c != 0` и `FUN_1201fab4(...,4) > 14`: `f *= DAT_12123f08`;
  round; clamp 0..50.

`FUN_1201e92c` (вес, RVA `0x1e92c`) → (cur,max):
- cur (если `DAT_12106ab8+0x8c==0`): `round(vtable[+0x3c](person))`,
  иначе `13`;
- max: `a=FUN_12020620`, `b=FUN_120205b8`, `lvl=FUN_1201fb10`;
  `f = FUN_1201b1c4((a+b)*20 + lvl, 0x1e)`;
  если `FUN_1201fab4(...,6) > 4`: `f *= DAT_12123e80`;
  если `DAT_12106bc0+0x8c==0` и `(this+0xf8 & 0x2000)`: `f *= DAT_12123e90`;
  round; clamp 1..9999.

Классификация:
- `FUN_1201fab4` (skill, RVA `0x1fab4`) — просто:
  `clamp(this+0xc? base[id] : base[id] + bonus[id], 0, max)`; поля
  `+0x7c+4*id` (база) и `+0x198+4*id` (бонус при `this+0xc!=0`).
- `FUN_1201b1c4` (RVA `0x1b1c4`, size **2267**, 39 вызовов) — центральное
  числовое преобразование (возвращает `float10`), с большими буферами и
  обработкой ошибок; **нужен отдельный разбор** (это общий примитив для
  всех статов). Это главный блокер P5c2.
- Item/person **vtable** методы (`+0x18/+0x28/+0x2c` item, `+0x3c`
  person) и float-константы `DAT_12123f*`, `DAT_12123e80/e90` — извлечь
  из образа (`llvm-objdump -d` + `.data`).

Следующие шаги экстракции (точные RVA):
- `FUN_1201b1c4` (0x1b1c4) — разобрать математику по дизассемблеру;
- `FUN_120204e8` (0x204e8), `FUN_12020620` (0x20620), `FUN_120205b8`
  (0x205b8) — простые ли чтения полей;
- vtable item `+0x18/+0x28/+0x2c` и person `+0x3c` — найти таблицы;
- константы `DAT_12123f14/0c/10/08/18`, `DAT_12123e80/e90` (float/double);
- флаги `DAT_12106ab8+0x8c`, `DAT_12106bc0+0x8c`, `this+0xf8&0x2000`.

## Открытые вопросы / следующие шаги экстракции

- Где `Server.dll` считает статы (имя функции, offset структуры на
  персоне), какие поля пишет (например `+0xdc/+0xe4/+0x24/+0x2c` в
  клиентском объекте — какое соответствие серверным полям).
- Как экипировка/скиллы/атрибуты входят в урон/сопротивления
  (таблицы, целочисленность/FPU).
- Единицы: `Вес` `132/204.6` (max — capacity от силы), сопротивления
  в `%`.
- Значения `—` в оригинале: когда поле реально пустое/0 (напр. урон без
  оружия) — нужно отличать 0 от «нет данных».

## Non-goals

- Изменение существующих runtime/систем (P5a/P5b) кроме чтения.
- Точные FPU-режимы сверх уже закрытых (D-062/D-065), если формула
  целочисленная.
- Мультиплеер/синхронизация.
