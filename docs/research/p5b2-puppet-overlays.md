# P5b2-1 — Paper-doll overlays (`puppet_name`) — research

Дата: 2026-11-24. Статус: закрыт (геометрия доказана, реализовано).

## Источники

- `Client.dll` SHA-256
  `FBF213B4B820E767A529556D0F7E4D29EE2202E7E39C3E49043F49D55DAB5C16`
- Дамп `.local/decomp/client/decompiled.c` (Ghidra).

## Факты

1. ITM поле `puppet_name` содержит конкретный кадр оверлея, например:
   - armor 318 `type=12`: `puppet\Bronya\Almaz\00.bmp`
   - elbarms 397 `type=14`: `puppet\ponozhi\Goluboi\01.bmp`
   - helmet 280 `type=11`: `puppet\shlemy\Cherny\00.bmp`
   - axe 486 `type=1`: `puppet\Topory\Dvuruchnye\almaz\01.bmp`
   - ring 233 `type=17`: `puppet\ring\00.bmp`
2. Ассеты — `items/res/<puppet_name>` (1938 файлов
   `items/res/puppet/...`), 8bpp BMP с magenta-фоном `#FF00FF`.
3. Каждый кадр — общий «холст» с частью фигуры, содержимое смещено
   внутри (замеры `PIL`):
   - armor `190x230`, контент `(98,9)-(183,90)`
   - helmet `168x267`, контент `(127,5)-(156,40)`
   - pants `175x147`, контент `(99,4)-(165,136)`
   - axe `208x176`, контент `(114,20)-(187,144)`
   - ring `183x135`, контент `(96,1)-(180,6)`
   Т.е. все кадры выровнены по общему углу (низ-право), поэтому стопка
   оверлеев складывается в одетую фигуру.
4. Рисование — `FUN_120683a8` (RVA `0x683a8`), порядок масок
   `0x200000, 0x100000, 0xF8000, 0x4000, 0xC00000, 0x3000`; активный
   набор оружия/щита `this+0x1d4` (0=A, 1=B); отрисовка через
   `FUN_12015d38(текстура, surface/rect, x, y, src_rect, 1)`.
5. В декомпиляции `y = (H - tex_h) - 0x92`, где `H` —
   `DAT_1210fd04+0x46bc` (высота рендера, 768); `x = 5` либо
   crop-сдвиг `min(tex_w-30, 0x87)`, `0x87 = 135 = 270/2`.
   Сигнатура `FUN_12015d38` и смысл регистровых аргументов
   восстановлены неуверенно — **якорь и масштаб не доказаны**.
6. Пробная композиция всех кадров с общим низ-правым якорем
   `(278,616)` даёт цельную одетую фигуру, но она смещена вправо
   относительно нарисованного тела в BMP; точное совмещение не
   подобрано.

## Геометрия (доказано дизассемблером + проверка композиции)

Дизассемблер (`llvm-objdump`, ImageBase `0x12000000`):

- `FUN_12015d38(this=текстура, surface, x, y, src_rect, flag)` —
  программный blit в surface-структуру `{0,0,w,h,pixels,pitch}`;
  `x,y` — левый-верхний угол назначения, `src_rect=0` = весь спрайт.
- Вызывающий `FUN_120661cc` (RVA `0x661cc`) рисует сначала фон в
  surface куклы (x=0,y=0), затем `FUN_120683a8(this, &surface)`.
- `FUN_120683a8`, ветка «не аксессуары» (`mask & 0xF0000 == 0`):
  `FUN_12015d38(tex, surface, 5, (H - tex_h) - 0x92, 0, 1)`, где
  `H = DAT_1210fd04+0x46bc` = высота рендера (768), `0x92 = 146`.
  Т.е. левый край `x=5`, низ `622` (768−146).
- Аксессуары (`mask & 0xF0000`): рисуется половина холста 135 px:
  - `mask & 0x50000` (ring A `0x10000`, bracer A `0x40000`):
    src `(0,0,min(w,135),h)` в `x=5`;
  - иначе (amulet `0x8000`, ring B `0x20000`, bracer B `0x80000`):
    `x0 = (w<135 ? w-30 : 135)`, src `(x0,0,w,h)` в `x=x0+5`.
- Порядок слоёв (внешний цикл масок):
  `0x200000` (elbarms) → `0x100000` (armor) → `0xF8000`
  (amulet/rings/bracers) → `0x4000` (helmet) → `0xC00000`
  (weapon/shield) → `0x3000`.
- Активный набор оружия: `this+0x1d4` (0=A, 1=B); неактивная пара
  (`0x1000`/`0x400000` при 1, `0x2000`/`0x800000` при 0) не рисуется.
- Проверка композиции (`PIL`): armor 318 + helmet 280 + elbarms 397 +
  axe 486, левый край `x=5`, низ `y=622` — оверлеи точно ложатся на
  нарисованное тело в `inventory_secondary.bmp` (шлем на голову,
  броня на торс, поножи на ноги).

## Нужно для закрытия

- Реализация в порте: состав оверлеев из `Item::puppet_name`, якорь
  `(5, 622)`, половинный холст для аксессуаров, порядок масок,
  активный набор A/B; тесты на синтетическом и real slot0.
- Слой inventory (P5b1 `InventoryOverlay`) — отдельный follow-up,
  механика та же.
- Активный набор оружия/щита из сейва (`local_player+0x6E4`) пока не
  моделируется: порт по умолчанию считает активным набор A (как и
  иконки слотов), второй набор не рисуется.
