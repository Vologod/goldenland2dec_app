## Текстовые примитивы (подтверждены дизассемблером)

- `FUN_12030980` (RVA `0x30980`) — `TextOutA(hdc, x, y, text)`;
  `y` = верх клетки символа.
- `FUN_12030a88(this, hdc, x, y, textId, widthBox, heightBox)` (RVA
  `0x30a88`, `ret 0x18`). Локализованный текст по id. Если
  `widthBox != -1` и `textW < widthBox`: `x += (widthBox - textW) >> 1`;
  если `heightBox != -1` и `cellH < heightBox`:
  `y += (heightBox - cellH) >> 1`, где `cellH = abs(*(*font+8))`.
  `-1` = без центрирования (лево/верх).
- `FUN_12030b4c(...)` (RVA `0x30b4c`) и `FUN_12030a04(...)` (RVA
  `0x30a04`) — то же центрирование для строки и числа.
- Уточнение против декомпилятора: сигнатура `FUN_12030a88` содержит 6
  стек-аргументов (`ret 0x18`); декомпилятор показал 4. Порядок:
  `hdc, x, y, textId, widthBox(-1=нет), heightBox(-1=нет)`.

## Вертикальное выравнивание (GDI cell)

- GDI `TextOutA(hdc, x, y, ...)` при `TA_TOP`: `y` = верх клетки,
  baseline = `y + tmAscent`. Порт `Font::draw_text(y)` ставит
  baseline = `y + hhea_ascent`; `hhea`-ascent **не включает line
  leading**, поэтому текст листа выше оригинала («прижат к верху»).
- **Важно про оракул:** `.local/p7b2/characteristics.png` — это рендер
  **порта** (все combat/resistance, включая «Класс брони»/«Вес»/
  «Базовая точность», показаны как `—`, чего в игре не бывает).
  Настоящий оригинал — новые снимки
  `.local/p7b3/original_characteristics.png` / `original_skills.png`
  (реальные значения, `-/+`, `64%`, `132/204.6` и т.п.). Первый фикс
  калибровался по порт-рендеру (half leading) — это было неверно.
- Замер против **настоящего** оригинала (diff по фону BMP, y-диапазон
  пикселей текста): порт был на **2.5–3.5 px** выше во всех секциях
  (метки, значения, имя, вкладки, заголовки, навыки).
- **Фикс:** `y += Font::line_height() - Font::text_height()`
  (**полный** line leading = ~5.2 px при 16 px, ~5.6 px при 17 px) в
  `draw_text_rect`. После фикса против нового оригинала:
  - метки/значения/имя/заголовки — расхождение 0–1 px;
  - страница навыков — 0–1 px.
- Метод: `glpak extract ... inventory_secondary.bmp / inventory_skills.bmp`;
  diff `original_characteristics.png`/`original_skills.png` против
  порт-рендера (diff RGB > 60). Значения у оригинала и порта разные
  (другой сейв), но метки/боксы/цифровая вертикаль сравнимы.

## Шрифт/размер

- Симптом: верхняя полоса (имя+вкладки) в оригинале крупнее и ЖИРНЕЕ
  (GDI synthetic bold weight 600). bold-TTF в игре нет (только
  `pala.ttf`), значит GDI синтезирует вес; заголовки секций мельче.
- Фикс в порте: отдельный «верхний» шрифт `pala.ttf` **20 px** +
  синтетический bold (двойная отрисовка `x`, `x+1`) для имени/вкладок;
  заголовки секций/групп → **16 px**; строки — 16 px.
- Ширина после (diff по фону):
  - верхняя полоса: `ХАРАКТЕРИСТИКИ` orig 204 vs port 196 (−4%),
    `НАВЫКИ` 95 vs 90, `Вертас` 64 vs 63;
  - заголовки: `СОСТОЯНИЕ` 102 vs 103, `СОПРОТИВЛЕНИЕ` 147 vs 147,
    `БОЕВЫЕ ХАРАКТЕРИСТИКИ` 221 vs 224 — совпало;
  - строки ещё +6% (`Телосложение` 100 vs 106), группы +12%
    (`Навыки Воина` 102 vs 114) — остаток фейса `pala.ttf` vs системного
    Palatino Linotype (оба размера/ширины одновременно не совпадают).
- Точка правки: `CharacterOverlay::draw_tabs`/`top_font()`
  (`src/app/...`), `glgame::load_character_fonts` (20 px top, 16 px
  title).

## Чёткость текста (2026-11-25)

- Симптомы: текст «смазанный» (и жирный, и обычный), у заглавных `Т`/`Б`
  «обрезан» верхний штрих.
- Причина 1 (мыло): UV атласа глифов использовали «полутексельный»
  инсет `u0=(x+0.5)/W`, `u1=(x+w-0.5)/W` при отрисовке 1:1. Это даёт
  систематический полу-пиксельный сдвиг → билинейное размытие (и
  ослабление крайних строк глифа → верх `Т`/`Б` «исчезал»).
- Причина 2: дробные позиции отрисовки (полный line-leading 5.2 px,
  центрирование `*0.5`) → линейный фильтр мылит.
- Фикс (`src/render/src/font.cpp`):
  - UV без инсета: `u0=x/W`, `u1=(x+w)/W` (при 1:1 и целых координатах
    сэмплы попадают точно в центр текселей → чётко);
  - новый параметр `Font::draw_text(..., bool snap=false)` — округление
    quads глифов до целых пикселей; лист (`draw_text_rect`) вызывает
    `snap=true`. Прочие экраны не меняют поведение.
- Проверка: `font_tests` 9/9, `character_overlay_tests` 9/9 (154),
  `dialog_overlay_tests` 9/9, `inventory_overlay_tests` 19/19; полный
  `ctest` 21/21.
