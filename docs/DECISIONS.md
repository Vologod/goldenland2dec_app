Пересматривать только с новой записью.

|---|---|---|---|
| D-001 | 2026-10-19 | Целевая игра — «Златогорье 2» v1.3, каталог `I:\Games\Златогорье-2` (`GoldenLand.exe`). | Явное указание пользователя; это базовая игра, а не аддон «Холодные небеса». |
| D-002 | 2026-10-19 | Стратегия — чистая реконструкция движка на переносимом C++20 + SDL2. | Только этот путь даёт поддерживаемый исходник и нативный Android. Машинный декомпил MSVC C++ не собирается без многолетней ручной чистки; гибридная эмуляция не даёт исходника. |
| D-003 | 2026-10-19 | Данные игры используются оригинальные, только во время выполнения; ассеты не коммитятся и не распространяются. | Правовая безопасность и требование пользователя. |

| D-007 | 2026-10-19 | Третьи стороны вендорятся в `third_party/` с фиксированными версиями и лицензиями. | Воспроизводимость сборки и работа офлайн. |

| D-009 | 2026-10-19 | Один подпроект = одна спецификация = один план = одна задача. | Ограничивает объём и предотвращает смешивание слоёв. |
| D-010 | 2026-10-19 | Первый подпроект — P0 (ассеты и форматы), а не рендер. | Фундамент без платформенных зависимостей; проверяется на ПК; переиспользуется всеми слоями. |
| D-011 | 2026-10-19 | `normalize_virtual_path` — UTF-8-aware с фолбэком на cp1251: если строка — валидный UTF-8, регистр понижается для ASCII и кириллицы U+0410–U+042F, прочие многобайтовые последовательности копируются без изменений; иначе применяется побайтовый cp1251-casefold. Имена путей в `.pak` считаются ASCII. | На границе API строки UTF-8, а имена внутри архивов — cp1251; простая побайтовая схема повреждала валидный UTF-8. |
| D-012 | 2026-10-19 | ITM-парсер пропускает неизвестные значения `ItemType` (документированы 0–28) как есть; условные блоки выбираются по числовому типу. Хвостовые байты после разобранной записи считаются ошибкой формата. | Данные — источник истины; отказ по неизвестному типу мог бы отбросить валидные предметы; строгий хвост ловит рассогласование разбора (пересмотреть, если реальные `.itm` окажутся с padding). |
| D-013 | 2026-10-19 | Формат payload `.pak`: `size` в FAT — распакованный размер; по `offset` лежит `mode : uint32` (0 — raw ровно `size` байт, иначе — `stored : uint32` + zlib-поток длиной `stored`, разворачивающийся до `size`). Поле `VfsEntry` переименовано в `uncompressed_size`. | Проверено на всех `.pak` каталога `I:\Games\Златогорье-2\Data`; прежняя трактовка (mode 0 = zlib с `unpacked_size`, mode != 0 = raw) неверна: `mount` падал с `entry outside archive`. |
| D-014 | 2026-10-19 | ITM: блок `damage` (6×uint32) присутствует у типов 0–7, 11–14 и **28**; у типа 15 (браслеты) его нет. Блок эффектов (`u32 count` + `count×16` байт) есть у всех типов, **кроме типа 21 (книги)**: книги заканчиваются после блока заклинания (`spell_id` + резервный `u32`). Тип 22 (свитки) сохраняет блок эффектов. | Проверено на всех 1848 `items/data/*.itm`: до правки 84 файла (книги 21, камни 28) не парсились. |
| D-015 | 2026-10-19 | Лимиты CSX: `kMaxPixels = 64 Ми`, `kMaxDimension = 1'000'000`; пустые (size 0) `.csx` считаются отсутствующими ресурсами и не декодируются. | Проверено на всех непустых `.csx` целевой сборки: 19 704 декодированы, максимум 1400×41 700 = 58 380 000 пикселей; одна пустая запись `levels/pack/tl41/bitmaps/minimap.csx`. |
| D-016 | 2026-10-19 | SDL2 — исключение из D-007: подключается через CMake `FetchContent` с пином `release-2.32.10`, статической сборкой (`SDL_SHARED=OFF`, `SDL_STATIC=ON`) и неглубоким клоном на этапе configure. Первый configure требует сеть; исходники скачиваются под `build/`, а не в `third_party/`. | Так требует утверждённая спецификация P1; крупный исходник SDL2 не хранится в репозитории, но версия зафиксирована, поэтому сборка воспроизводима после первого скачивания. |
| D-017 | 2026-10-19 | LVL-парсер требует, чтобы после 12-го блока (`BLK_LFLS`) не оставалось байт; иначе — ошибка формата. Моделируемые блоки также должны расходовать payload ровно, `SENV` — включая строки и записи звуков. | Все 175 реальных `levels/lvl/*.lvl` не имеют хвостов; строгая проверка ловит рассогласование размера блока и разбора. Пересмотреть при появлении расширенного формата. |
